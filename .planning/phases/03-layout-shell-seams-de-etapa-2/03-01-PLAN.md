<objective>
Prove end to end that a deferred-measurement consumer can attach to this theme without a refactor,
and let JavaScript into the theme for the first time through a gate rather than through a habit.

Purpose: SHELL-01 and SHELL-03 are only worth anything if "connecting Etapa 2" turns out to be an
edit inside one already-rendered file rather than a rebuild of the head. This plan settles that by
building the thinnest complete path: the shell renders a real seam snippet in the exact head
position the attribution script needs, the theme's first JavaScript module publishes an event bus,
and a consumer attaches to that bus and receives a real event. Everything after this — the other
event names' emitters, the header, the footer, the contract document — expands out from a slice
that has already been proven.

Output: the corrected document head, the no-op Etapa 2 seam, the event bus and accessibility
helper as the theme's first script asset, the surface checker's JavaScript allowlist, and the
document landmarks the rest of the phase and every later phase build on.
</objective>

<decisions>
Planner-resolved questions this plan implements. Veto any of these at plan review or at the Task 1
checkpoint.

- **The announce helper lives inside the event bus module, not in a second file** (Claude's
  discretion, research Open Question 4). One script asset instead of two, roughly ten extra lines,
  and the live region it writes into is rendered by the same shell that loads it. A separate file
  would only pay off if a later phase loaded the helper without the bus, which is implausible.
- **The module is a classic immediately-invoked function, not a module with imports.** Skeleton has
  no import map and no bundler, and adopting one is explicitly out of scope. A deferred script tag
  and a namespace on the global object need nothing else.
- **The head order fix ships in this plan rather than being deferred.** This is the plan that
  reorders the head anyway; leaving the character set several kilobytes deep while touching the
  lines around it would be choosing to keep a known accented-character hazard (Pitfall 1, WR-04).
- **The focus trap is not written.** It has no consumer until the cart drawer and the size guide
  exist, and a trap with no consumer is orphan code that still has to be tested and maintained
  (D-08).
</decisions>

    returns a handle; `off` takes that handle and removes the listener. There is no private

    dispatch calls.
