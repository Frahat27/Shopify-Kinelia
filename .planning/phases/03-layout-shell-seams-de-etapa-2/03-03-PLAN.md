<objective>
Give the storefront a header that says "this is Kinelia" and gets out of the way, with an
announcement strip above it that stays pinned on a phone without stealing the fold.

Purpose: SHELL-02's header half. The traffic arriving here came from a Meta advertisement straight
to a product page, on a phone, to buy on impulse. The header's entire job is brand recognition plus
a route to the cart — every additional affordance is conversion leaking out of the page. At the same
time the user asked for the announcement strip to stay pinned alongside the header on phones, which
puts a fixed block of pixels permanently across the most expensive part of the screen. This plan
builds both, reserves their height so nothing shifts, and writes the stacking order down as named
tokens so the Phase 6 cart drawer inherits it instead of guessing.

Output: the two brand marks vendored and optimised, the browser icon, the announcement strip as its
own section with its locale copy, the rebuilt header, and the shell's reserved-height and stacking
tokens.
</objective>

<decisions>
Planner-resolved questions this plan implements. Veto any of these at plan review.

- **The stacking order is header below floating action button below overlay**, as three named
  tokens. Research suggested putting the floating button above the cart drawer; that is wrong for
  this store — a drawer that a chat button punches a hole through looks broken. The drawer and any
  future modal take the overlay level and cover both. Deviation from the research recommendation,
  recorded in the ledger.
- **No fallback browser icon in an older raster format.** The vector mark covers every browser this
  audience uses, and a second icon is another asset the funnel pays for on every page. Research open
  question 5 recommended the same.
- **The announcement message ships from the locale, with an optional theme-editor override that
  starts empty.** The locale stays the source of the shipped default, which is the repository rule
  that keeps user-facing strings out of templates; the override exists because a merchant changing a
  promotional line should not need a code deploy. When the override is blank the locale value
  renders.
- **The optional link is a URL setting, not a text setting.** A free-text setting interpolated into
  a link target is an injection surface with no upside; the constrained type is validated by the
  platform.
- **The header keeps the starter's account component and cart counter verbatim.** They already do
  the right thing, the account component is the platform's own, and reimplementing either buys
  nothing.
</decisions>
