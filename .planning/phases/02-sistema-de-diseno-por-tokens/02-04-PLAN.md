<objective>
Make Argentine Spanish the theme's native language and give every later copy phase a contract it
cannot accidentally violate.

Purpose: DESIGN-04 asks for an es-AR voseo locale scaffold with all UI text coming from locale
files. That is half a translation job and half a governance job. The translation makes the store
speak the way Kinelia's customer speaks. The governance — the six approved calls to action, the
root promise, the mandatory legal legend as a reusable key, and the prohibited-claims list in a
repository document — is what stops Phase 7's landing copy or Phase 11's page copy from inventing
a medical claim that a health-adjacent product sold in Argentina must never make.

Output: the storefront and schema locales renamed from English to Spanish and translated to
voseo; the Kinelia brand namespace with its six calls to action, the root promise and the legal
legend; the locale half of the executable contract; and the copy rules written down where the
next phase will find them.
</objective>

<decisions>
Developer-resolved questions this plan implements. Veto any of these at plan review.

- **RQ-3 (resolved) — the theme is Argentine Spanish only; the English locale is dropped, not
  kept.** Both files are renamed with git and translated in place. Keeping an English locale
  alongside would trigger the linter's matching-translations rule, which then requires every key
  to stay in sync across both files forever — pure tax for a single-market Argentine store. **But
  this is verified, not assumed:** research assumption A5 notes that Shopify's documentation
  states only that exactly one default file is permitted, and is silent on whether an English
  file must exist at all. Task 1 therefore ends by running the linter with Spanish as the sole
  default. If it objects, a minimal non-default English file is added, and the finding is recorded
  in the ledger rather than being silently worked around.
- **The rename is a rename, not a deletion.** Phase 1's standing rule is that the theme reduces by
  not referencing and never by deleting. A locale rename is not a deletion of render surface, and
  using git's rename keeps the file's history attached to its content (Pitfall 9). This is
  recorded in `OVERRIDES.md` as a locale note.
- **Prices stay out of the locale.** The manual's reference prices are placeholders, and a price
  in a translation file is a price no one can change without a code deploy. They belong to the
  Phase 4 offer metaobject.
- **The legal legend is a plain key, not a markup key.** Unsuffixed locale keys are auto-escaped
  when rendered; only keys carrying the html suffix render markup. The legend is plain text, so it
  gets a plain key and the escaping stays on.
</decisions>
