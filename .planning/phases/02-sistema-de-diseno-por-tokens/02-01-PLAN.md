<objective>
Prove the whole Kinelia token path with one real brand colour, then make the path
machine-enforced before anything else is built on it.

Purpose: DESIGN-02 says a rebrand is a token change, not a component change. That promise is
worthless unless something fails loudly the first time a literal colour value lands in a
component stylesheet. This plan wires the shortest possible real slice of the architecture
described in D-17 — theme setting to schema default to Liquid custom property to a consuming
CSS rule inside the document the layout actually renders — and lands the executable copy of
DESIGN-02 that guards it. Everything the rest of the phase adds (nine more colours,
typography, spacing, self-hosted fonts, the design primitives, the locale) is expansion out
from this proven slice.

Output: the primary green flowing end to end; `assets/base.css` created and loaded;
`scripts/check-tokens.mjs` as the executable contract; that checker in `npm run lint` and in
the required pull-request gate alongside the two Phase-1 checkers that were still laptop-only.
</objective>

<decisions>
Developer-resolved questions this plan implements. Veto any of these at plan review.

- **RQ-4 (resolved): `check-tokens.mjs` runs in CI, not only locally.** It is added to the
  `run:` block of the existing required `Theme Check (gate)` step in `.github/workflows/ci.yml`,
  and `check-allowlist.mjs` plus `check-secrets.mjs` are backfilled into that same step —
  closing the Phase-1 residual recorded as T-01-12 in `01-SECURITY.md`. The job name and
  display name stay frozen because branch protection keys off them.
- **D-17 (locked) shape confirmed:** brand token values live as schema `default:` in
  `config/settings_schema.json`; `snippets/css-variables.liquid` reads them and emits `:root`
  custom properties; component CSS references `var(--*)` only. The checker enforces the last
  clause.
- **Checker scope, deliberately narrow:** spacing literals (`1rem`, `gap: 16px`) are NOT
  checked. `sections/header.liquid` already carries them and machine-enforcing a spacing scale
  would be pure noise. Spacing-token discipline is a code-review concern.
- **One named exemption:** `sections/hello-world.liquid` is the starter demo section that plan
  01-04 de-referenced and `ALLOWLIST.md` files under "Presente, no renderiza". It carries two
  literal colour values and a shadow declaration. It is exempted by exact path, with the
  exemption comment pointing at that document. It is not cleaned and not deleted — the repo
  rule is reduce-by-not-referencing.
</decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| theme editor (merchant input) → inline style block in the document head | A stored setting value is interpolated into CSS that every page renders |
| contributor → component stylesheets | A literal colour value or font name committed here silently breaks the rebrand-in-one-place contract |
| developer laptop → pull-request gate | A check that runs only locally is a check that eventually stops running |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | Free-text theme setting interpolated into the inline style block | high | mitigate | Checker rule 3 resolves every `settings.<id>` the emitter references to its schema entry and fails unless the input type is a colour picker, a select or a range — a text or richtext setting can never reach the token block |
| T-02-02 | Tampering | A colour picker cleared in the theme editor yields an empty string and an invalid declaration | medium | mitigate | Every interpolated colour pipes a Liquid `default:` fallback; checker rule 4 fails when one does not |
| T-02-03 | Tampering | A checker whose scan silently matches nothing reports success forever | high | mitigate | Empty-scan-fails guard (rule 9), mirroring `check-allowlist.mjs` lines 101-108; the verify block runs three negative cases that must each make the checker exit non-zero |
| T-02-04 | Tampering | A token rename misses a consuming file and a component silently loses its colour | high | mitigate | Checker rule 5 fails on any `var(--x)` whose name is defined neither in the emitter's root block nor locally in the same file |
