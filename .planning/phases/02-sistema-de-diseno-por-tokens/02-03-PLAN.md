<objective>
Ship the brand's two type families from the theme's own assets, then build the design primitive
set that every later phase's components will inherit.

Purpose: DESIGN-03 asks for a `base.css` carrying reset, type scale, colours, spacing, buttons
and form primitives, all token-derived. Plans 02-01 and 02-02 built the token vocabulary; this
plan spends it. The font work comes first in the same plan because the type scale is meaningless
until the faces it scales actually load, and because the layout has been rendering in system
fallback fonts since plan 02-02 removed the starter's font plumbing.

Output: five subset font files with recorded provenance and measured weight; five font-face
declarations and exactly two preloads; and `assets/base.css` filled out from the one tracer rule
to the complete primitive set — flat, token-only, and legible for an audience reading on a phone
at low brightness.
</objective>

<decisions>
Developer-resolved questions this plan implements. Veto any of these at plan review.

- **RQ-5 (resolved) — the button carries the two-pixel radius, badges carry zero.** The button
  uses the radius token, which resolves to two pixels, matching the icon system in the brand
  manual. The zero-radius token exists and is reserved for badges, which the manual specifies as
  straight rectangles. No large radius appears anywhere (D-10, D-12).
- **D-08 (resolved) — self-host, and here is the honest reason.** The two families ship as subset
  files in `assets/`. This is chosen for the largest-contentful-paint budget and for visitor
  privacy — a third-party font host adds two connections on the critical path and leaks every
  visitor's IP address to it. It is *not* chosen to keep the linter green: research verified that
  the remote-asset theme-check rule is a **warning**, not an error, so `--fail-level error` would
  never have failed on a third-party font link. The hard gate is rule 7 of
  `scripts/check-tokens.mjs`, added in plan 02-01.
- **Static instances, not variable fonts.** Two weights of the heading family and three of the
  body family. At three weights or fewer per family, static subset files total fewer bytes than a
  variable file.
- **Swap, not optional.** The font-display strategy is swap: for this audience, seeing the text
  immediately in a fallback and then in the brand face beats not seeing it at all. Preloading the
  two first-paint weights shrinks the swap window to near zero.
- **Full performance measurement stays in Phase 13.** The Lighthouse harness does not run clean
  on this Windows machine against the local development proxy (`.planning/WINDOWS.md` entry 7).
  This plan measures the font bytes directly from the filesystem and records them; the throttled
  mobile run is Phase 13's.
</decisions>
