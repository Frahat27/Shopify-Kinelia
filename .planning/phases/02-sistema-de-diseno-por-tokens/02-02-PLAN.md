<objective>
Expand the proven one-token slice into the complete Kinelia brand surface, and move the theme
off the starter's token vocabulary onto Kinelia's own.

Purpose: DESIGN-01 requires the brand's colour, typography and spacing to live in one place and
reach the page as custom properties. Plan 02-01 proved the path with a single colour; this plan
fills it — ten brand colours with editor controls, the two type families as constrained
selections rather than a font-library picker, the base-4 spacing scale, and the flat-system
radius pair. It also does the rename once and cleanly: the starter's `background`/`foreground`
vocabulary becomes Kinelia's `bg`/`text`, in every consuming file, in one commit, guarded by the
checker's undefined-property rule so a missed file cannot ship silently.

Output: the whole token vocabulary emitted from one file; the starter's font-library plumbing
removed from both the emitter and the layout head before it can render a broken preload; and
the deviations on the record.
</objective>

<decisions>
Developer-resolved questions this plan implements. Veto any of these at plan review.

- **RQ-1 (resolved) — spacing and radius are static custom properties in the one token file, not
  theme-editor settings.** This is a deliberate deviation from the literal wording of ROADMAP
  Phase 2 Success Criterion 1 ("los tokens … espaciado … están en `settings_schema.json`"). Only
  colour and typography are editor-tunable. Rationale: merchants retune brand colours and fonts;
  no merchant has ever retuned a spacing scale, and eight range inputs is bad editor UX. Because
  the scale still lives in the single token file, DESIGN-02 ("a rebrand is a token change, not a
  component change") holds for spacing exactly as it does for colour. **Recorded in
  `OVERRIDES.md` as a named deviation in Task 3.** The one exception is the corner radius, which
  stays a range input because the starter already exposes it — but its maximum drops to the
  brand ceiling so the editor cannot break the flat system (D-10, Pitfall 8).
- **RQ-2 (resolved) — rename the starter token names to the Kinelia scheme, no alias layer.**
  `--color-background` becomes the Kinelia background token, `--color-foreground` becomes the
  Kinelia text token, the starter's font-family and input-radius properties are replaced by the
  brand equivalents. Every consuming file is updated in this same plan. An alias layer would
  leave two live names for one concept forever; Phase 2 is the token phase and the blast radius
  is fully enumerated — three consuming files, nine references.
- **D-18 (resolved) — the two type families are `select` settings with fixed options, not a
  font-library picker.** Self-hosting (plan 02-03) means the font-library object and its filters
  do not apply. One option per family today, with room for more.
- **Ordering note.** The starter's head font block is removed in this plan, not deferred to plan
  02-03. The moment the font-library setting leaves the schema, that block evaluates against a
  nil object and renders an empty preload link on every page (Pitfall 1). Removing it here leaves
  the theme rendering in system fallback fonts for exactly one commit; plan 02-03 restores the
  brand faces. Recorded in `OVERRIDES.md` as a scoped pre-empt of Phase 3's shell work.
- **Correction carried from research.** The remote-asset theme-check rule is a *warning*, not an
  error, so `shopify theme check --fail-level error` would not have failed on a third-party font
  link. Self-hosting is chosen for the largest-contentful-paint budget and for visitor privacy —
  not because it keeps the linter green. The hard gate is rule 7 of `scripts/check-tokens.mjs`.
</decisions>
