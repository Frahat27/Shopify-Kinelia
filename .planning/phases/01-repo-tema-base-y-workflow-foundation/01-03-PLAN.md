<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull-request author → GitHub Actions runner | Untrusted code is checked out in a job that has access to repository secrets |
| GitHub Actions secrets → workflow logs | A credential printed once to a log is a leaked credential |
| npm registry → repository devDependencies | A dev dependency executes on the developer's machine |
| repository working tree → git history | An environment file committed once stays in history forever |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | `@lhci/cli` devDependency install | high | mitigate | Package-legitimacy gate + `gate="blocking-human"` checkpoint (Task 1) before adding it; the never-install prohibition covers the audited SLOP linter package; both action tags pinned to a major |
| T-01-07 | Elevation of privilege | `lighthouse.yml` pull-request job | high | mitigate | `pull_request` trigger only, asserted by a negative grep on the fork-privileged trigger; private repository; first-time-contributor workflow approval noted in the release runbook |
| T-01-08 | Information disclosure | Dev Dashboard credentials | high | mitigate | Credentials referenced only as `secrets.*`; no literal in any file; no echo of inputs; `.gitignore` covers `.env` and `.env.*` before any credential exists |
| T-01-09 | Denial of service | Lighthouse job hang (known action issue) | low | mitigate | `timeout-minutes: 25` on the job so the run fails visibly rather than pinning a runner |
| T-01-10 | Tampering | Weakened lint configuration | medium | mitigate | Performance-relevant rules asserted absent from the active configuration; every disabled rule requires a written justification comment |
</threat_model>
