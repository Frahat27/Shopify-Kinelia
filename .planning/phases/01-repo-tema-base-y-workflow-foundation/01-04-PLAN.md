<objective>
Reduce the base theme to what Kinelia actually renders — by allowlist and by not referencing,
never by deletion — and make that reduction machine-checkable.

Purpose: FOUND-03 exists so the theme stays lean as sections are added over twelve more phases. On
a starter that ships near-zero JavaScript, the risk is not over-stripping (there is nothing to
strip); it is under-building and then quietly re-importing bloat. The allowlist is the contract
that makes both failure modes visible.

Output: `ALLOWLIST.md` as the surface contract, `scripts/check-allowlist.mjs` as its enforcement,
the demo-section reference removed from the home template, and `OVERRIDES.md` reconciled to the
true state of every Phase 1 divergence.
</objective>

  <action>
    Apply the reduction by reference, not by deletion. Read every file under `templates/` and every
    section-group JSON file, and collect the section types they reference. For any reference to a
    starter demo section that `ALLOWLIST.md` places under `## Presente, no renderiza`, remove the
    reference from the JSON template and remove its entry from that template's `order` array. Leave
    the section `.liquid` file itself in the repository, untouched. Do not remove any file.

    If removing a reference would leave a template with an empty `sections` object, leave a single
    allowlisted section in place instead — an empty template is a blank route, which is a worse
    outcome than a placeholder.

    Write `scripts/check-allowlist.mjs` as an ES module using only the Node standard library, with
    two-space indentation, double quotes, comments in English and domain terms in Spanish, per the
    project conventions. It must:
    - Read every `*.json` file under `templates/` and every `sections/*-group.json`, parse each, and
      collect the `type` value of every entry in its `sections` object.
    - Compare that set against the render allowlist. Keep the allowlist as an exported constant
      array in this script — this file is the enforced copy, and `ALLOWLIST.md` is its human
      explanation. Report every referenced section type that is not on the list, naming the file it
      came from.
    - Fail when any file directly under `assets/` has a `.js` or `.mjs` extension. Phase 1 adds no
      JavaScript; later phases update this rule together with the allowlist when they legitimately
      add a module.
    - Fail when any filename under `assets/` matches a known heavy front-end library (check for
      jquery, swiper, react, vue and alpine as case-insensitive substrings).
    - Fail when it found zero JSON templates to inspect — a scan that finds nothing must not report
      success, or the gate silently stops gating the first time a path changes.
    - Print one line per violation and exit with a non-zero status when there is at least one;
      print a one-line summary of how many templates and section types it checked and exit 0
      otherwise. Use `process.exitCode` rather than `process.exit()` so the event loop drains on
      Windows, per the project convention.

    Add a `lint:allowlist` script to `package.json` that runs the checker with Node, and extend the
    existing `lint` script so that a single invocation runs both the theme linter and the allowlist
    checker. Add a root-anchored `/scripts/` entry to `.shopifyignore` so the checker is never
    uploaded to a theme by a CLI push.

    Run the theme linter and the allowlist checker; both must pass before this task is done.
  </action>
