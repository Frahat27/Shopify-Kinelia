<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `staging` branch → published storefront | A misconnected branch puts unreviewed code in front of paid traffic |
| pull request → protected branch | Branch protection is the only thing standing between a red check and a merge |
| unpublished staging theme → the public | Preview links are unlisted, not authenticated |
| GitHub Actions job → Dev Dashboard credentials | The performance job holds store credentials at run time |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-24 | Elevation of privilege | Branch protection with a mistyped check name | high | mitigate | Required-check names taken verbatim from the plan 01-03 summary; proven by a real red run blocking a real merge, not by reading the settings page |
| T-01-25 | Tampering | Staging branch connected to the published theme | high | mitigate | Explicit mapping stated in the checkpoint instructions and in `docs/RELEASE.md`; the store asserted to have exactly one published theme |
| T-01-26 | Information disclosure | Unlisted staging preview link with test prices | medium | mitigate | Theme stays unpublished; the preview link is recorded in the private setup document, not published; stale development themes removed as they accumulate |
| T-01-27 | Information disclosure | Credentials exposed in a workflow run log | high | mitigate | The performance workflow reads credentials as secrets only and echoes no input; the pull request used for verification originates from a branch in this private repository, never from a fork |
| T-01-28 | Repudiation | A gate recorded as satisfied without evidence | medium | mitigate | Acceptance criteria require run URLs and an observed blocked merge; a timed-out or unauthenticated performance job must be recorded as an open finding rather than passed over |
| T-01-29 | Denial of service | Throwaway verification pull request left open | low | mitigate | Prohibition against merging it; open-pull-request count asserted to be zero and the branch deleted |
</threat_model>
